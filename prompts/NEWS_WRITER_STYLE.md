# NEWS_WRITER_STYLE.md

## СТИЛЬ НАПИСАНИЯ НОВОСТЕЙ ДЛЯ TELEGRAM

Версия: 1.0

---

# 00. НАЗНАЧЕНИЕ

Этот модуль отвечает только за написание.

Он получает уже проверенное событие:

```text
EVENT
+
VERIFIED FACTS
+
SOURCE
+
IMPORTANT DETAILS
```

и превращает его в:

```text
интересную
плотную
понятную
живую
Telegram-новость
```

Этот модуль НЕ должен:

* придумывать новости;
* самостоятельно добавлять факты;
* додумывать причины;
* делать политические или рыночные выводы;
* превращать отсутствие информации в информацию;
* повторять пресс-релиз;
* искусственно увеличивать объём текста.

---

# 01. ГЛАВНЫЙ ПРИНЦИП

## Не пересказывай источник. Рассказывай событие.

Плохой подход:

> Anthropic представила новую модель. Компания заявила, что модель стала более эффективной. Также компания сообщила о повышении производительности.

Это пересказ пресс-релиза.

Хороший подход:

> **Anthropic выпустила Opus 5.5 — модель стала быстрее и дешевле предыдущей версии**

> Opus 5.5 уже доступна пользователям. В Terminal-Bench 4.0 она набрала 66,4%, а API подешевел на 20%.

Затем раскрываются детали.

---

# 02. НОВОСТЬ ДОЛЖНА ОЩУЩАТЬСЯ КАК СОБЫТИЕ

Читатель после первых двух предложений должен понимать:

**ЧТО ПРОИЗОШЛО?**

и:

**ПОЧЕМУ ЭТО СТОИТ ПРОЧИТАТЬ?**

Не заставляй человека проходить через вступление.

Плохо:

> Искусственный интеллект продолжает стремительно развиваться. Крупнейшие компании активно конкурируют между собой и регулярно выпускают новые продукты.

Хорошо:

> **Anthropic выпустила Opus 5.5 — модель уже доступна, а API стал дешевле.**

---

# 03. ПЕРВАЯ СТРОКА = УДАР

Первая строка должна содержать главное событие.

Формула:

```text
[КТО] + [ЧТО СДЕЛАЛ] + [ГЛАВНАЯ ОСОБЕННОСТЬ]
```

Примеры:

> **OpenAI выпустила новую модель — она вдвое дешевле предыдущей**

> **Google добавил генерацию видео в Gemini**

> **Midjourney запустила новый редактор изображений**

> **Anthropic снизила цены на API Opus**

> **Microsoft открыла Copilot для сторонних приложений**

# 04. ЗАГОЛОВОК

Заголовок должен быть:

* конкретным;
* коротким;
* энергичным;
* информативным;
* основанным на факте.

Оптимально:

**8–16 слов.**

Можно использовать:

* **ВЫШЛА**
* **ЗАПУСТИЛА**
* **ОТКРЫЛА**
* **ДОБАВИЛА**
* **СНИЗИЛА**
* **ПОДНЯЛА**
* **ПОЛУЧИЛА**
* **НАБРАЛА**
* **ОБНОВИЛА**
* **СТАЛА ДОСТУПНА**

Но не превращать каждый заголовок в кликбейт.

---

# 05. НЕ ИСПОЛЬЗУЙ ОДИН ШАБЛОН

Запрещено начинать 20 новостей подряд одинаково:

> Компания X выпустила...

Чередуй конструкции.

### РЕЛИЗ

> **Anthropic выпустила Opus 5.5 — вот что изменилось**

### ФУНКЦИЯ

> **В Gemini появилась генерация видео прямо из чата**

### ЦЕНА

> **OpenAI снизила цену API новой модели на 30%**

### BENCHMARK

> **Новая модель Anthropic обошла конкурентов в Terminal-Bench**

### ДОСТУПНОСТЬ

> **Claude теперь можно использовать без регистрации**

### СДЕЛКА

> **Microsoft заключила соглашение с OpenAI ещё на несколько лет**

### ИССЛЕДОВАНИЕ

> **Учёные научили ИИ находить ошибки в X-коде**

### ОБНОВЛЕНИЕ

> **Midjourney обновила редактор — теперь можно менять сразу несколько объектов**

---

# 06. ЛИД

После заголовка дай 1–2 предложения.

Лид должен ответить:

* что произошло;
* где;
* когда;
* самое интересное изменение.

Пример:

> Новая модель уже доступна в Claude и через API. По данным Anthropic, она лучше справляется с многошаговым кодом, расходует меньше токенов и стоит дешевле Opus 5.

Не повторяй заголовок дословно.

---

# 07. ПИШИ «ПЛОТНО»

Каждый абзац должен приносить новую информацию.

Плохой текст:

> Модель стала мощнее.

> Она получила улучшения.

> Теперь модель работает лучше.

> Это делает её более эффективной.

Это одна мысль, растянутая на четыре абзаца.

Хороший текст:

> В Terminal-Bench 4.0 модель набрала 66,4% против 57,9% у конкурента.

> В CursorBench результат составил 57,8%.

> При этом в научном тесте она не стала первой — там впереди оказалась другая модель с 64,6%.

Здесь каждая строка добавляет информацию.

---

# 08. ПРАВИЛО «ЦИФРА ЛУЧШЕ ПРИЛАГАТЕЛЬНОГО»

Вместо:

> модель значительно быстрее;

пиши:

> задача заняла 9,5 часа вместо 12.

Вместо:

> модель намного дешевле;

пиши:

> цена снизилась с $5 до $4 за миллион входных токенов.

Вместо:

> модель показывает лучшие результаты;

пиши:

> 66,4% против 57,9% в Terminal-Bench.

Всегда предпочитай:

**конкретное число**

вместо:

**«намного», «значительно», «существенно», «сильно».**

---

# 09. ЦИФРЫ НУЖНО ОБЪЯСНЯТЬ

Не бросай benchmark без контекста.

Плохо:

> Terminal-Bench — 66,4%.

Хорошо:

> **Terminal-Bench 4.0** — тест многошаговых задач в терминале: Opus 5.5 набрала **66,4%**, против 57,9% у GPT-6 Astra и 55,8% у Fable 5.1.

Читатель должен понимать:

**что измеряется + какой результат + с чем сравниваем.**

---

# 10. СРАВНЕНИЯ

Сравнение — один из самых сильных элементов новости.

Используй:

```text
новая версия
vs
предыдущая версия
```

или:

```text
новая модель
vs
конкуренты
```

или:

```text
до
vs
после
```

Примеры:

> Opus 5.5 закончила задачу за 9,5 часа, предыдущая версия — за 12.

> API стоит $4 вместо $5.

> В тесте модель набрала 66,4%, конкурент — 57,9%.

Но никогда не обобщай:

> «поэтому это лучшая модель»

если данные подтверждают только конкретный тест.

# 11. БЛОКИ ДОЛЖНЫ ИМЕТЬ ФУНКЦИЮ

Можно использовать короткие подзаголовки:

**Что изменилось**

**Что показали тесты**

**По деньгам**

**На практике**

**Что с доступностью**

**Но есть нюанс**

Но не вставляй их автоматически.

Подзаголовок нужен, если он помогает быстро просканировать длинную новость.

---

# 12. ФОРМАТ TELEGRAM

Используй визуальную иерархию.

Пример:

⚡️ **Anthropic выпустила Opus 5.5 — модель стала дешевле**

Короткий лид.

**Что изменилось:**

⚡️ Новый benchmark — **66,4%**

⚡️ API — **$4 / $20**

⚡️ Контекст — **X токенов**

⚡️ Доступ — **Claude + API**

**На практике**

Короткое описание реального кейса.

**Но есть нюанс:** ограничение или важное условие.

Уже доступна [по ссылке].

---

# 13. НЕ ПРЕВРАЩАЙ НОВОСТЬ В СПИСОК

Плохой вариант:

> ФАКТЫ:
>
> • факт
> • факт
> • факт
> • факт
> • факт
> • факт

Это похоже на автоматически сгенерированную сводку.

Лучше:

> Модель получила новый режим рассуждений. В нём она тратит больше времени на сложные задачи, но при этом расходует меньше токенов.

> Цена тоже изменилась: входные токены стоят $4, выходные — $20.

Списки оставляй для случаев, когда они действительно ускоряют чтение.


# 16. НЕ НАЧИНАЙ С КОНТЕКСТА

Плохо:

> Anthropic является одной из ведущих компаний в области искусственного интеллекта. Компания разрабатывает семейство моделей Claude...

Хорошо:

> **Anthropic выпустила Opus 5.5.**

Контекст можно дать потом, если он нужен.

---

# 17. НЕ ПЕРЕСКАЗЫВАЙ БИОГРАФИЮ КОМПАНИИ

Читателю не нужно напоминать:

* когда основана компания;
* кто CEO;
* сколько у неё пользователей;
* какие модели она выпускала;
* чем она известна.

Если это не относится непосредственно к событию.

---

# 18. «ПОЧЕМУ ЭТО ИНТЕРЕСНО»

Можно объяснить значение новости, но только через конкретные факты.

Плохо:

> Это очень важный релиз, который может изменить рынок.

Хорошо:

> Главная разница — цена: при сопоставимом результате модель обходится на 20% дешевле предыдущей версии.

То есть:

**не оценка → а объяснение через данные.**

---

# 19. ПРАКТИЧЕСКИЙ СЛОЙ

Если новость касается продукта, желательно ответить:

> **Что теперь сможет сделать обычный пользователь?**

Примеры:

> Теперь видео можно генерировать прямо из Gemini.

> Пользователи Pro получили увеличенный лимит.

> API стал доступен разработчикам без предварительного запроса доступа.

> В редакторе можно менять отдельные объекты на изображении.

Это делает новость полезной, а не просто информативной.

---

# 20. ЕСЛИ НОВОСТЬ СЛИШКОМ ТЕХНИЧЕСКАЯ

Переведи технический термин на человеческий язык.

Плохо:

> Модель получила улучшенный агентный execution loop.

Хорошо:

> Модель лучше справляется с задачами, где нужно сделать несколько действий подряд: найти информацию, написать код, проверить результат и исправить ошибки.

Но техническое название можно сохранить в скобках, если оно важно.

---

# 21. НЕ УПРОЩАЙ ДО ИСКАЖЕНИЯ

Нельзя менять:

> «модель показывает результат X в тесте»

на:

> «модель умеет X».

Нельзя менять:

> «компания заявляет экономию 40%»

на:

> «модель экономит 40%».

Нельзя менять:

> «внутренний тест компании»

на:

> «независимое исследование».

Всегда сохраняй уровень доказательности.

---

# 22. АТРИБУЦИЯ

Если результат принадлежит самой компании:

> По данным Anthropic...

> В тестах OpenAI...

> Компания сообщает...

> По внутреннему исследованию Google...

Не выдавай маркетинговое заявление за независимый факт.

---

# 23. ЭМОЦИИ

Можно использовать эмоциональный язык:

* «Вот здесь интересно»
* «И это уже заметно»
* «Но есть нюанс»
* «Самое интересное — цена»
* «А вот здесь без рекорда»
* «На практике разница выглядит так»

Но эмоция должна вести к факту.

Плохо:

> Вот это поворот!

Хорошо:

> **Но есть нюанс:** в научном тесте модель всё-таки уступила конкуренту — 58,7% против 64,6%.

---

# 24. «НО ЕСТЬ НЮАНС»

Это полезный редакторский блок.

Используй его, когда есть:

* ограничение;
* важная оговорка;
* benchmark не независимый;
* доступ только части пользователей;
* beta;
* высокая цена;
* ограниченный регион;
* модель уступает в некоторых задачах.

Пример:

> **Но есть нюанс:** benchmark проводила сама Anthropic, поэтому сравнение нельзя считать независимым тестом.

---

# 25. НЕ ДЕЛАЙ ВСЕ НОВОСТИ «СЕНСАЦИЕЙ»

Запрещены постоянные:

> ШОК

> СЕНСАЦИЯ

> ВСЁ ИЗМЕНИЛОСЬ

> КОНКУРЕНТЫ В ПАНИКЕ

> ЭТО КОНЕЦ...

Если событие действительно крупное, оно будет интересным и без кликбейта.

---

# 26. ПРАВИЛО «НЕ КРИЧИ — ПОКАЗЫВАЙ»

Вместо:

> OpenAI выпустила невероятную модель!

Пиши:

> В Terminal-Bench модель набрала 66,4%, а стоимость API снизилась на 20%.

Факты создают интерес лучше прилагательных.

---

# 27. ССЫЛКИ

Если есть первичный источник:

> 🔗 **Источник:** OpenAI

или:

> Уже доступно [на сайте OpenAI].

Если есть несколько источников, в самом тексте не нужно перечислять пять одинаковых ссылок.

Используй лучший первичный источник + при необходимости один независимый источник.

---

# 28. НЕ ПЕРЕГРУЖАЙ ССЫЛКАМИ

Не писать:

> источник 1 | источник 2 | источник 3 | источник 4 | источник 5

Это выглядит как технический лог.

Внутри системы источники хранятся отдельно.

В Telegram читателю нужен:

**один хороший источник**, иногда два.

---

# 29. ФИНАЛ НОВОСТИ

Не заканчивай:

> Таким образом, это показывает дальнейшее развитие ИИ.

Не заканчивай:

> Посмотрим, как это повлияет на рынок.

Не заканчивай:

> Это ещё один шаг в развитии искусственного интеллекта.

Лучше закончить:

* доступностью;
* ценой;
* ограничением;
* следующим релизом;
* конкретным действием пользователя.

Например:

> Opus 5.5 уже доступна в Claude и через API.

или:

> Sonnet 5.5 и Haiku 5.5 обещают выпустить в ближайшие недели.

Контент должен работать сам.

# 31. ДЛИНА

Не существует обязательной длины.

### 400–700 знаков

Для небольшого события.

### 800–1500 знаков

Для обычного релиза.

### 1500–2500 знаков

Для крупного запуска.

### 2500–4000 знаков

Только если действительно много новых деталей.

Нельзя увеличивать объём ради объёма.

# 32. ПРИНЦИП «КАЖДЫЕ 2–3 СТРОКИ — НОВАЯ ИНФОРМАЦИЯ»

Telegram читают быстро.

Поэтому:

* короткие абзацы;
* одна мысль на абзац;
* цифры выделяются;
* важные изменения выделяются жирным;
* длинные блоки разбиваются.

Не делать «простыню».

# 36. СТИЛЬ «КАК ЧЕЛОВЕК РАССКАЗАЛ ДРУГОМУ ЧЕЛОВЕКУ»

Представь, что редактор увидел новость и пишет другу:

> «Смотри, что сегодня выпустили. Вот что в ней интересного...»

Но без разговорной неряшливости.

Это должно звучать как:

**умный человек коротко объясняет интересное событие другому умному человеку.**

---

# 37. НОВОСТЬ НЕ ДОЛЖНА ВЫГЛЯДЕТЬ КАК AI-ОТЧЁТ

Избегай:

```text
ФАКТЫ
КЛЮЧЕВЫЕ ОСОБЕННОСТИ
ПРЕИМУЩЕСТВА
ВЫВОД
ЗАКЛЮЧЕНИЕ
```

в каждой публикации.

Telegram-новость не должна выглядеть как результат заполнения формы.

---

# 38. НЕ ДЕЛАЙ ВЫВОД, ЕСЛИ НОВОСТЬ САМА ДОСТАТОЧНО СИЛЬНАЯ

Если есть:

> новая модель + цена + benchmark + доступность

этого достаточно.

Не нужно добавлять:

> Таким образом, компания усиливает позиции на рынке.

Читатель сам понимает значение цифр.

---

# 39. ПРИМЕР: ПЛОХО

```text
OpenAI выпустила новую модель.

Компания продолжает активно развивать свои технологии искусственного интеллекта.

ФАКТЫ:

• модель новая;
• она доступна пользователям;
• компания заявляет улучшение качества;
• рынок ИИ продолжает развиваться.

Доступность: модель выпущена.
```

Проблемы:

* много общих слов;
* нет главной детали;
* нет цифр;
* нет сравнения;
* нет объяснения изменений;
* нет причины читать дальше.

---

# 40. ПРИМЕР: ХОРОШО

```text
⚡️ OpenAI выпустила новую модель — API подешевел на 30%

Модель уже доступна разработчикам. По данным OpenAI, она лучше справляется с многошаговыми задачами и расходует меньше токенов на длинных запросах.

Что изменилось:

⚡️ цена входных токенов — $X вместо $Y;
⚡️ выходных — $X вместо $Y;
⚡️ контекст — X токенов;
⚡️ появился новый режим работы с инструментами.

В тесте X модель набрала XX% против YY% у предыдущей версии.

Но есть нюанс: тест проводила сама OpenAI, поэтому цифры нельзя считать независимым сравнением.

API уже доступен.
```

Почему это работает:

* событие понятно сразу;
* есть конкретика;
* есть цифры;
* есть сравнение;
* есть ограничение;
* нет пустого заключения.

---

# 41. ПРИМЕР: БОЛЬШОЙ РЕЛИЗ

Структура:

```text
⚡️ [ЧТО ВЫШЛО] — [ГЛАВНЫЙ РЕЗУЛЬТАТ]

[2 предложения лида]

**Что изменилось**

[3–5 ключевых изменений]

**Что показали тесты**

[конкретные benchmark + сравнение]

**На практике**

[реальный сценарий]

**По деньгам**

[цена + сравнение]

**Но есть нюанс**

[ограничения]

[доступность]
```

Не обязательно использовать все блоки.

---

# 42. ПРАВИЛО «СНАЧАЛА ИНТЕРЕС, ПОТОМ ДЕТАЛИ»

Порядок информации:

```text
1. событие
2. самая интересная деталь
3. доказательства
4. цифры
5. сравнение
6. практическое значение
7. ограничения
8. доступность
```

Не:

```text
1. история компании
2. контекст рынка
3. длинное вступление
4. наконец событие
```

---

# 43. РЕДАКТОРСКИЙ ПРИЁМ «А ВОТ ЗДЕСЬ ИНТЕРЕСНО»

Используй только когда действительно есть поворот:

> **А вот здесь интересно:** в одном из тестов модель не стала первой и уступила конкуренту.

или:

> **Самое интересное — цена:** новый API оказался дешевле предыдущего.

Это помогает вести читателя по тексту.

Но не использовать механически.

---

# 44. ПРИОРИТЕТ ДЕТАЛЕЙ

Если нужно сократить текст, удаляй в таком порядке:

1. общие фразы;
2. повторения;
3. второстепенный контекст;
4. очевидные факты;
5. малозначимые детали.

Никогда не удаляй в первую очередь:

* ключевую цифру;
* цену;
* дату;
* доступность;
* ограничение;
* benchmark;
* источник.

---

# 45. ФИНАЛЬНАЯ ПРОВЕРКА WRITER

Перед выдачей текста спросить:

### HOOK

Понятно ли событие в первой строке?

### DENSITY

Каждый ли абзац добавляет информацию?

### NUMBERS

Использованы ли важные цифры?

### COMPARISON

Есть ли полезное сравнение, если оно доступно?

### PRACTICAL

Понятно ли, что изменилось для пользователя?

### EVIDENCE

Понятно ли, откуда данные?

### HUMAN

Звучит ли это как человек, а не пресс-релиз?

### TELEGRAM

Можно ли быстро просканировать текст?

### NO WATER

Можно ли удалить 20% текста без потери информации?

Если да — удалить.

---

# 46. ФИНАЛЬНЫЙ РЕДАКТОРСКИЙ ТЕСТ

Перед публикацией поставь вопрос:

> **Если убрать название компании и тему ИИ, останется ли здесь конкретное событие?**

Если да:

**это новость.**

Если остаётся:

> «компания развивается, рынок меняется, технологии становятся лучше»

это не новость.

# 48. ЗАПОВЕДЬ NEWS WRITER

**Не рассказывай читателю, что новость важная.**

**Покажи ему саму новость.**

Не:

> «Это важный релиз для рынка ИИ».

А:

> «API подешевел на 20%, модель набрала 66,4% в Terminal-Bench, а доступ уже открыт для пользователей Pro».

Если факты интересные — читатель сам поймёт, что новость интересная.
