# PROMPTS v2 — спецификация системы промптов и конвейера

> Целевая архитектура. Канал — это **конфигурация**, а не набор правил внутри промптов.
> Текущее состояние (как работает сейчас) — в `PROMPTS.md`.
> Легенда: ✅ реализовано · 🟡 частично · ⬜ нужно сделать.

## 0. Принципы

1. **Не один супер-промпт, а система специализированных шагов + общая память + JSON.**
2. Каждый шаг — отдельный промпт с одной задачей и структурированным выходом.
3. Память накапливается: каждый пост оставляет след (DNA), каждая неделя — правило.
4. Аналитика не заканчивается отчётом: она **меняет параметры следующей генерации**.
5. Универсальность: новый канал/язык/ЦА/визуальный стиль добавляются конфигом, не переписыванием.

## 1. Пайплайн

```
CONTENT MEMORY → СТРАТЕГ → ПЛАНИРОВЩИК → HOOKS → ГЕНЕРАТОР → ANTI-REPEAT
→ FACT/SAFETY → РЕДАКТОР → QUALITY CONTROL → ВИЗУАЛ → ПУБЛИКАТОР → АНАЛИТИКА → LEARNING LOOP ↺
```

| Шаг | Промпт | Задача | Статус |
|---|---|---|---|
| 00 | `GLOBAL_RULES` | единые запреты/форматы (из конфига канала) | ✅ (в `PROMPT_CHANNEL_*` + конвейере) |
| 01 | `STRATEGIST` | цели канала, веса метрик, контент-микс | ⬜ |
| 02 | `PLANNER` | темы + **контентные механики** → карточки | 🟡 (слоты есть, механик нет) |
| 03 | `HOOK_GENERATOR` | 5 заходов, выбор одного, запрет повторов типов | ⬜ |
| 04 | `GENERATOR` | **одна карточка → один пост** | 🟡 (генерирует пачкой) |
| 05 | `ANTI_REPEAT` | смысловой поиск повторов (DNA + эмбеддинги) | 🟡 (SimHash, без DNA) |
| 06 | `FACT_SAFETY` | факты, обещания, безопасность | 🟡 (evergreen + новости) |
| 07 | `EDITOR` | стиль, структура, действие в конце | 🟡 (частично в конвейере) |
| 08 | `QUALITY_CONTROL` | скоринг + `publish` (технический фильтр) | ⬜ |
| 09 | `IMAGE_GENERATOR` | `visual_required` + концепт + промпт | 🟡 (картинка всегда) |
| 10 | `PUBLISHER` | статусы, retry, анти-повтор | 🟡 (есть, без retry-полей) |
| 11 | `ANALYTICS` | наблюдение → гипотеза → действие | ⬜ |
| 12 | `LEARNING_LOOP` | правила для следующей недели | ⬜ |

## 2. Конфигурация канала (универсально)

```json

  "title": "Нейро-секреты",
  "content_mode": "evergreen",          // evergreen | current | mixed
  "audience": "женщины 25–45, не технари",
  "tone": "тёплый, как подруга, без жаргона",
  "goals": { "retention": 25, "saves": 30, "shares": 25, "reactions": 10, "comments": 10 },
  "rubrics": {
    "secret":      { "length": [300, 600], "visual_required": false },
    "prompt":      { "length": [300, 800], "visual_required": true  },
    "before_after":{ "length": [400, 900], "visual_required": true  },
    "interactive": { "length": [150, 400], "visual_required": false },
    "lifehack":    { "length": [300, 700], "visual_required": false },
    "tools":       { "length": [500, 1000], "visual_required": false },
    "review":      { "length": [500, 1000], "visual_required": false }
  },
  "emoji": { "min": 0, "max": 4, "rule": "только для структуры, не механически" },
  "hashtags": { "min": 0, "max": 3, "rule": "иногда можно без них" },
  "visual": {
    "style": "мягкий свет, тёплые тона, минимализм, без текста на картинке",
    "people": "естественная разнообразная внешность без акцента на этничность (если не часть сюжета)"
  },
  "links": { "allowed": true, "rule": "официальные сайты/GitHub, без партнёрских" }
}
```

## 3. Контент-память (`content_memory.json` / SQLite) ⬜

Что хранится и отдаётся в промпты:

```json
{
  "recent_posts":    ["последние 50 постов: id, тема, hook, механика, дата"],
  "used_hooks":      ["последние 30 заходов (с типами)"],
  "used_topics":     ["темы, которые уже были"],
  "used_prompts":    ["промпты, которые уже публиковались"],
  "used_mechanics":  ["механики: prompt / before_after / multiple_variants / ..."],
  "rules":           ["правила от LEARNING LOOP (см. §12)"]
}
```

Правило для генератора:

> **Не создавай пост, повторяющий предыдущую публикацию по смыслу**, даже если формулировка
> отличается. «Добавь роль специалиста» и «Представь, что ты эксперт» — одна и та же идея.

## 4. Content DNA (для каждого поста) ⬜

```json
{
  "topic": "планирование меню",
  "audience": "женщины / семья",
  "problem": "нет идей, что готовить",
  "mechanic": "prompt",
  "hook_type": "ошибка",
  "benefit": "экономия времени",
  "emotion": "облегчение",
  "format": "prompt",
  "difficulty": "beginner"
}
```

По DNA работает анти-повтор: система понимает «я уже писала про меню», даже если текст другой.

## 5. Шаги-промпты

### 00_GLOBAL_RULES (из конфига канала)

- `content_mode = evergreen`: запрещены даты, новости, версии, свежие релизы, цены, статистика,
  а также **относительные даты: «сегодня», «завтра», «вчера», «на этой неделе», «в этом месяце»,
  «сейчас», «недавно», «только что», «скоро»** → заменять на «когда понадобится», «в любой момент»,
  «при следующем использовании».
- `content_mode = current` (новости): даты/бренды/цифры разрешены — это суть.
- Запрещены непроверяемые обещания: гарантии результата, «всегда», «никогда», «100%», «идеально»
  как обещание, мед/финансовые/юридические рекомендации, утверждения о возможностях ИИ,
  зависящие от конкретного сервиса.
- Эмодзи 0–4 (по структуре), хэштеги 0–3 (иногда без).
- Длина — по рубрике (§2), а не «400–700 всем».
- Ссылки: официальные — можно; партнёрские/реферальные — нельзя.

### 01_STRATEGIST ⬜

```
Ты — стратег канала «{{title}}». Цели и веса: {{goals}}. Прошлые правила: {{rules}}.
Определи на неделю: контент-микс по рубрикам (доли), 2–3 фокуса, чего избегать.
Выход: JSON {"mix": {"prompt": 0.4, ...}, "focus": ["..."], "avoid": ["..."]}
```

### 02_PLANNER (карточки, не тексты) 🟡

```
Ты — контент-планировщик канала «{{title}}».
Дано: микс {{mix}}, память {{content_memory}}, сетка {{grid}}.
Создай карточки постов (НЕ тексты):
{"post_id": "ns-001", "rubric": "secret", "topic": "...", "audience_problem": "...",
 "mechanic": "before_after|prompt|multiple_variants|checklist|myth|story|interactive",
 "hook_type": "боль|любопытство|результат|ошибка|наблюдение",
 "desired_action": "скопировать запрос", "visual": "before_after"}
Правила: не повторять темы/механики из памяти; hook_type не повторять два раза подряд.
```

### 03_HOOK_GENERATOR ⬜

```
Для карточки {{card}} сгенерируй 5 заходов:
1) через боль, 2) через любопытство, 3) через результат, 4) через ошибку, 5) через наблюдение.
Выбери лучший (по ясности + обещанию пользы), верни {"hook": "...", "hook_type": "..."}.
Не использовать тип, который был в предыдущем посте.
```

### 04_GENERATOR (одна карточка → один пост) 🟡

```
Ты — автор канала «{{title}}». Тон: {{tone}}. Формат: {{rubric}}, длина {{length}}.
Карточка: {{card}}. Hook: {{hook}}.
Собери пост: hook → суть → польза → действие. Правила 00_GLOBAL_RULES.
Верни JSON: {"text": "...", "hashtags": [], "content_dna": {...}, "visual": {"required": true/false, "concept": "..."}}
```

### 05_ANTI_REPEAT ⬜

```
Сравни пост с памятью: темы, hooks, промпты, механики, смысл (DNA).
Если смысл повторяет прошлое — {"duplicate": true, "reason": "...", "closest": "ns-123"}.
Иначе {"duplicate": false}.
```

### 06_FACT_SAFETY 🟡

```
Проверь: даты/новости/версии/цены/статистику (для evergreen), относительные даты,
обещания («гарантированно», «всегда», «100%», «идеально»), мед/фин/юр советы,
утверждения о возможностях конкретных сервисов.
Выход: {"ok": true} или {"ok": false, "issues": ["..."], "fixed": "исправленный текст"}.
```

### 07_EDITOR 🟡

```
Отредактируй: ясность, короткие абзацы, одно действие в конце, длина по рубрике,
эмодзи 0–4 по структуре, хэштеги 0–3. Не меняй смысл. Верни текст.
```

### 08_QUALITY_CONTROL ⬜ (обязателен перед публикацией)

```
Оцени пост (не переписывай):
{"value": 0-10, "originality": 0-10, "clarity": 0-10, "saveability": 0-10,
 "shareability": 0-10, "hook": 0-10, "actionability": 0-10,
 "repetition": 0-10, "risk": 0-10, "publish": true/false, "notes": "..."}
publish = value>=7 AND clarity>=7 AND actionability>=7 AND repetition<=3 AND risk==0
```

**Saveability — главный сигнал канала:** «интересно» ≠ «сохраню, пригодится».

### 09_IMAGE_GENERATOR 🟡

```
Только если visual.required = true.
Концепт: {{visual.concept}}. Стиль канала: {{visual.style}}.
Требования: без текста на картинке; без знаменитостей; люди — естественная разнообразная
внешность без акцента на этничность (если не часть сюжета).
Верни {"prompt": "...", "style_tags": [...]}.
```

Рубрики без обязательной картинки: короткий секрет, лайфхак, инструменты, разборы.
(Снижает визуальный шум.)

### 10_PUBLISHER ✅ + доработки ⬜

Правила:
- `published` → **никогда** не публиковать повторно; есть `message_id` → не отправлять снова.
- `scheduled_at < now` → проверить, не пропущена ли публикация (и опубликовать/пометить `missed`).
- Ошибка → `retry` с ограничением (`retry_count`, `last_error`, `updated_at`).
- Лог: JSONL `{ts, post_id, status, message_id, error}`.

### 11_ANALYTICS ⬜

```
Данные за неделю: {{metrics}}. Веса целей: {{goals}}.
Дай: 1) наблюдения, 2) гипотезы, 3) действия. Формат:
{"observation": "...", "hypothesis": "...", "action": "...", "confidence": "низкая|средняя|высокая"}
Не оптимизируй под реакции в ущерб цели канала — считай по весам {{goals}}.
```

Пример: «посты с готовым промптом → больше сохранений» → «аудитории важнее инструмент, чем
объяснение принципа» → «увеличить долю actionable-контента».

### 12_LEARNING_LOOP ⬜

```
На основе отчёта обнови правила для следующей недели:
{"rules": ["+ больше практических промптов", "+ больше интерактивов", "- меньше абстрактных советов"]}
Правила попадают в content_memory.rules и в 01_STRATEGIST.
```

```json
  "retry_count": 0, "last_error": "", "updated_at": "2026-09-22T09:01:00+03:00"
}
```

## 7. Статусы v2 ⬜

```
idea → planned → generated → review → approved → scheduled → publishing → published
                                                                        ↘ failed
     ↘ rejected                                                          ↘ archived
```

Поля: `retry_count`, `last_error`, `updated_at`.
Маппинг с текущими: `pending ≈ review`, `approved/scheduled/published/rejected` — совпадают.

## 8. Дорожная карта внедрения

**Этап 1 (быстрые победы, не ломая текущее):**
1. ⬜ `visual_required` по рубрикам (сейчас картинка — почти всегда).
2. ⬜ Эмодзи 0–4 и хэштеги 0–3 (правка `ADAPTER_SYSTEM`/`NEWS_SYSTEM`).
3. ⬜ Длина по рубрикам вместо «400–700 всем».
4. ⬜ Убрать «славянскую внешность» из глобальных правил → в конкретные визуальные задания.
5. ⬜ Относительные даты («сегодня/скоро/недавно») в запреты.
6. ⬜ Обещания-запреты («гарантированно», «всегда», «100%») в фактчекер.

**Этап 2 (память и качество):**
7. ⬜ Content DNA у постов + `content_memory.json` (последние 50 постов, hooks, темы, механики).
8. ⬜ Анти-повтор по смыслу (DNA + SimHash).
9. ⬜ QUALITY_CONTROL со скорингом (перед постановкой в `pending`).
10. ⬜ Hook Generator (5 типов, без повторов подряд).

**Этап 3 (обучение):**
11. ⬜ Сбор аналитики по постам (сохранения/реакции/пересылки) — через Telegram API (для каналов)
    или вручную.
12. ⬜ ANALYTICS + LEARNING_LOOP → правила в память → планировщик.
13. ⬜ Стратег (веса целей, микс) в конфиге канала.

**Этап 4 (масштаб):**
14. ⬜ Конфиг каналов (`channels.json`) как единственный источник правил.
15. ⬜ Новый канал/язык/ЦА — добавление конфига без правки кода.
